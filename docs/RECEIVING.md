## Failures retained and repaired

The first browser transport attempt failed before application navigation because the helper's host resolver rule blocked the literal loopback address. Explicit loopback exceptions corrected that receiving harness; external page requests remain blocked.

The first actual keyboard course reproduced a product defect: after a private commitment, a repeated held Enter activated the newly focused next-player reveal button. The original failure receipt is retained in `docs/evidence/held-enter-baseline.json`. The repair prevents repeated Enter/Space on that reveal control. The qualified course proves repeated Enter remains covered and release plus a fresh press still reveals normally.

Actual pixel review identified missing selected styling: boolean ARIA attributes had been emitted as empty strings. The DOM builder now emits explicit true/false values for ARIA; rendered state and semantic values are checked. Editing proposal JSON also now clears the previous approval controls immediately.

## Scope

This is finite-game implementation and application receiving, not a human accessibility study, hardware-switch evaluation, secure multiplayer assessment, model-utility result, NVIDIA/Nebius execution, public deployment, or competition submission.

The source pin used by the qualified browser run binds the renderer and pack implementation as well as rules/checker/fixtures. Future semantic changes require regenerated pins and applicable receiving; a previous successful receipt is not an authorization to activate changed code.
